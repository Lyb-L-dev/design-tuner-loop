# design-tuner-loop

**让 AI 生成的设计稿变成你自己能精确调整的东西 —— 不用 Figma、不用设计工具授权、不用排客户端白名单。**

一个 WorkBuddy Skill：产出「自带实时控制面板的 HTML 设计稿」，你拖滑块改设计，导出的数值**就是**最终会落地的 CSS 值，Agent 按这组值直接写生产代码。

> Turn an AI-authored mockup into something *you* can fine-tune with sliders. The exported numbers **are** the CSS values — no translation step, no Figma seat, no OAuth.

---

## 它解决什么问题

你可能遇到过这种对话：

> 「设计稿改一下，间距大一点，主色再深一点。」
> 「……具体多少？」
> 「你看着办吧。」

结果就是来回猜。而如果走 Figma 路线，又有两个隐性成本：

1. **Figma 里的帧不是最终交付物。** 每次在 Figma 里改完，Agent 都要重新读帧、重新理解、重新生成一遍 —— 有信息损耗，而且一旦代码里有了真实组件/状态/数据，Figma 稿就过期了，从「事实来源」退化成「参考图」。
2. **Figma 的「像素精确」最终还是要在 CSS 里再解一遍** —— 响应式换行、文字溢出、真实字体度量（Figma 的字体 ≠ 浏览器的字体）、无障碍对比度。

所以按阶段分：

| 阶段 | 谁更强 | 原因 |
|---|---|---|
| 早期探索（这个布局到底行不行） | Figma | 自由拖拽、多选对齐、组件变体 |
| **中期细化（间距节奏、字号阶梯、色彩系统）** | **本 Skill** | 导出的数值就是 CSS 值，无损 |
| 代码落地后的微调 | 直接改代码 | 改真实组件 |

**诚实说明它做不到什么**：不能拖拽元素、不能多选对齐分布、没有组件实例/变体、不能编辑任意属性、没有评论和版本历史。想要这些就用 Figma。

## 30 秒上手

对 Agent 说：

> 我要做一个「活动详情页」，先给我可调参数的版本，我自己调。

Agent 会产出一个自包含的 HTML 文件（左边设计稿、右边控制面板）。然后：

| 操作 | 效果 |
|---|---|
| 拖滑块 / 点取色器 | 设计稿**实时**跟着变 |
| 「底色」分段按钮 | 整页深浅色切换 |
| 「画布宽度」预设 | 手机 390 / 平板 768 / 桌面 1100，跨过 700px 时布局真的从单列翻成两列 |
| 主色选太浅 | **弹红框警告**并给出具体 WCAG 对比度比值（低于 3:1 按钮文字就瞎了） |
| 勾「标注模式」 | 页面上自动标出每一处间距（`↕` 纵向 / `↔` 横向）、内边距、画布宽度 —— 等价于 Figma 的量距工具 |

调完把结果交回给 Agent，三种方式任选：

- **导出参数** → JSON
- **复制 CSS** → 直接能贴进样式表的 `:root { ... }` 块
- **复制链接** → 一条包含全部参数的 URL，发给任何人打开都是同一个样子

> **关键一步：把导出的结果贴回给 Agent。** 让它按那组确切数字写生产代码 —— 这才是闭环的意义，而不是再"目测一遍"。

刷新不丢参数（自动存 localStorage）；点「重置」回到默认值。

## 仓库结构

```
.
├── SKILL.md                      Agent 执行手册：模式、契约、坑、检查清单
├── assets/
│   └── tuner-scaffold.html       脚手架：复制一份、换掉内容即可
├── scripts/
│   ├── scaffold.test.js          jsdom 逻辑回归测试（41 条）
│   └── browser_verify.py         真实 Chromium 布局回归测试（26 条）
├── README.md
└── LICENSE
```

**加一个可调参数只需要写一行。** `MANIFEST` 数组是唯一事实来源，控件、默认值、CSS 写入、持久化、导出全部由它派生：

```js
{group:'间距', key:'space', css:'--space', label:'组件间距',
 type:'range', min:4, max:36, step:1, unit:'px', def:16}
```

`css:null` 表示只存状态不写 CSS（比如主题开关）；`presets` 可以给滑块加快速跳转按钮。

## 移植到你自己的页面

1. 复制 `assets/tuner-scaffold.html` 到目标文件
2. 把 mock 部分换成真实页面的结构（根节点保留 `id="mock"`）
3. **把想调的值全部提升成 `.mock` 上的 CSS 自定义属性**，并在下方规则里用 `var()` 引用。任何写死的数字都调不了。
4. 精简 `MANIFEST` 到当前页面真正需要的那几个，把分组名和标签改成页面所用的语言
5. 页面里如果有横向 flex 行，把那个选择器加进 `drawAnnot()` 的 `groups` 列表，横向间距才会被测量
6. 用 `present_files` 打开，让它落到实时预览面板里
7. **用户导出后，严格按那些数值生成代码** —— 不要目测

## 跑测试

两套测试，因为抓的是不同类别的 bug。

```bash
# 1) 逻辑：jsdom
cd scripts
npm i jsdom
node scaffold.test.js                    # 期望 41 passed, 0 failed

# 2) 布局：真实 Chromium（自动探测 Edge / Chrome）
python browser_verify.py                 # 期望 26 passed, 0 failed
```

两套都支持传入任意副本路径，退出码 `1` 表示有失败、`2` 表示环境不可用，可直接接 CI。

**为什么必须有第二套**：jsdom 不做真实布局、不认 `@container`、不跑 CSS 过渡 —— 而本项目最危险的一类 bug 恰好全在这里。`browser_verify.py` 会启动真实无头浏览器、注入探针（不改动你的文件）、解析结果并自动清理。

### 改完脚手架请做负向验证

把断言针对的行为**故意改坏**，确认测试真的会红，再还原。否则很容易写出「无论有没有修复都通过」的假测试。已验证的对照：

| 改坏什么 | 期望失败数 |
|---|---|
| 让 URL hash 分支失效 | jsdom: 4 |
| 桩掉 `setProperty` 写入 | jsdom: 7 |
| 去掉标注徽标的清除 | jsdom: 2 |
| 把 `width` 加回 CSS 过渡 | Chromium: 3 |

最后一条是真踩过的坑：`.mock` 的过渡里一旦包含 `width`，改完宽度后 `getBoundingClientRect()` 会停在旧值约 150ms，标注模式就会按过渡中的中间尺寸测量，量出错误间距 —— **而且松手后不会自愈**。这个工具的全部价值就是测量和导出数值，几何必须即时确定，所以 `width` 不能有过渡。
